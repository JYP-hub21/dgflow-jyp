## 1. 프로젝트 개요

### 1.1 배경

동일유리(주)는 건축용 복층유리 제조업체로, 주문서(발주서/주문의뢰서)를 기점으로 전체 업무 프로세스가 시작된다. 현재 고객으로부터 이메일, 엑셀, 카카오톡 이미지 등 다양한 형식으로 주문을 수신하고 있으며, 이를 내부 표준 양식으로 변환하여 ERP에 입력하는 과정에서 비효율과 오류가 반복적으로 발생하고 있다.

2026년 8월 29일 PBL 교육에서 동일유리 임직원들과의 요구사항 분석 결과, 단순한 자동화 도구가 아닌 **주문에서 생산까지의 전체 업무 프로세스를 디지털화하는 웹 기반 워크플로우 시스템**의 필요성이 확인되었다.

### 1.2 목표

주문의뢰서 입력부터 승인, ERP 입력, 작업의뢰서 변환, 생산과정 모니터링까지를 하나의 웹 시스템에서 처리하여:

1. **데이터 무결성 확보** — 공사관리부와 고객이 승인한 정보의 손실 방지
2. **업무 효율 향상** — 양식 변환/표준화 수작업 제거, 데이터 변환 시간 절약
3. **오류 가능성 최소화** — 수작업 데이터 가공 과정 제거
4. **투명한 모니터링** — 고객, 공사관리부, 경영진 등 모든 이해관계자의 주문 현황 추적
5. **생산실적 관리 비용 절감** — 수작업 생산실적 정보 관리 자동화

### 1.3 기술 스택

| 구분 | 기술 | 비고 |
|------|------|------|
| 프론트엔드 | Next.js | Vercel 배포 (기존 활용) |
| 백엔드/DB | Supabase | PostgreSQL + Auth + RLS (기존 활용) |
| ERP 연동 | 엑셀 Import/Export | 바이투 ERP 호환 (16열 양식) |
| 데이터 | 기존 분석 데이터 | Project_planning.md 분석 결과 최대 활용 |

## 2. AS-IS 현황 분석

### 2.1 현재 업무 프로세스

```
고객                    공사관리부              경영지원팀              경영진           ERP(바이투)
 │                        │                      │                    │                │
 │──(이메일/엑셀/카톡)──→│                      │                    │                │
 │   다양한 형식          │                      │                    │                │
 │                        │──(비표준 엑셀)──────→│                    │                │
 │                        │  담당자별 다른 양식   │                    │                │
 │                        │                      │──(표준화 변환)────→│                │
 │                        │                      │  수작업 데이터 가공  │                │
 │                        │                      │                    │──(검토/승인)──→│
 │                        │                      │                    │               │──→ 작업의뢰서
 │                        │                      │                    │                │
 │  (모니터링 불가)       │  (모니터링 불가)      │                    │                │
```

### 2.2 핵심 문제점

| # | 문제점 | 상세 설명 | 영향 |
|---|--------|----------|------|
| P1 | **주문 양식 비표준화** | 고객이 이메일, 엑셀, 카카오톡 이미지 등 서로 다른 형식으로 주문. 공사관리부 담당자(6명 이상)도 각각 다른 양식의 엑셀을 작성 | 경영지원팀 변환 작업 증가 |
| P2 | **이중 변환 비용** | 공사관리부가 비표준 엑셀 작성 → 경영지원팀이 다시 표준 양식으로 변환. 동일 데이터를 2번 가공 | 인력/시간 낭비 |
| P3 | **데이터 오류 위험** | 수작업 데이터 가공(양식 변환, 규격 정리, 그룹핑) 과정에서 입력 오류, 누락, 불일치 발생 가능 | 품질 리스크, 재작업 비용 |
| P4 | **모니터링 불가** | 고객, 공사관리부, 경영진이 주문서 처리 상태를 실시간 확인할 수 없음. 진행 상황 파악을 위해 유선/메신저로 개별 확인 필요 | 의사소통 비용, 대응 지연 |
| P5 | **생산실적 수작업** | 생산관리팀이 수기로 생산실적(복층생산일지, 절단일보)을 엑셀에 입력. 공사관리부는 본인 주문의 생산 현황 확인 불가 | 관리 비용, 정보 단절 |

### 2.3 담당자별 발주서 양식 현황

현재 확인된 발주서 양식은 **6종 이상**이며, 담당자마다 완전히 다른 구조를 사용하고 있다:

| 담당자 | 양식 유형 | 시트 구성 | 특징 |
|--------|----------|----------|------|
| 안광식 상무 | 골조도+물량산출 | 17개 시트 | 골조도 기반, 차수별 분리, 매우 상세 |
| 이충언 이사 | 주문내역(EA) | 3개 시트 | 타입별 시트, NO/외판내판/두께/가로/세로 |
| 김길홍 과장 | 발주서(표) | 1개 시트 | 발주번호 체계, 위치/제품명/규격/수량 |
| 오동석 부장 | 발주서(세분화) | 32개 시트 | 날짜+내용별 시트, 수신/발신/검측자 |
| 외주 대진글라스 | 골조도+배치도 | 6개 시트 | 글레이징/알유리 구분 |
| 외주 정석개발 | 생산의뢰서 | 1개 시트(484행) | 대량 데이터, 품목/가로/세로/수량 |

## 3. TO-BE 시스템 설계

### 3.1 목표 업무 프로세스

```
고객                    공사관리부              경영지원팀              관리자(경영진)     ERP(바이투)
 │                        │                      │                    │                │
 │──(주문 요청)─────────→│                      │                    │                │
 │                        │                      │                    │                │
 │                        │──[웹 시스템 입력]     │                    │                │
 │                        │  표준화된 웹 폼       │                    │                │
 │                        │  주문의뢰서 자동 생성  │                    │                │
 │                        │                      │                    │                │
 │←──[초안 전송/승인]────│                      │                    │                │
 │   고객 승인 프로세스    │                      │                    │                │
 │──(승인)──────────────→│                      │                    │                │
 │                        │──────────(자동전달)──→│                    │                │
 │                        │                      │──[검토]            │                │
 │                        │                      │──────(검토완료)───→│                │
 │                        │                      │                    │──[최종승인]     │
 │                        │                      │                    │──────────────→│
 │                        │                      │                    │  ERP 데이터     │──→ 작업의뢰서
 │                        │                      │                    │  자동 생성      │
 │                        │                      │                    │                │
 │  [모니터링 가능]       │  [모니터링 가능]      │  [모니터링 가능]    │  [모니터링 가능] │
```

### 3.2 시스템 범위 (2개 영역)

#### 영역 1: 주문의뢰서 → ERP 입력 프로세스 (핵심)

주문정보 입력부터 ERP 입력 데이터 생성까지의 전체 워크플로우를 웹 시스템으로 구현한다.

#### 영역 2: 작업의뢰서 → 생산 모니터링 (확장)

주문의뢰서 기반으로 작업의뢰서를 생성하고, 생산과정 추적 및 생산실적 정보를 관리한다.

## 4. 사용자(Actor) 정의

### 4.1 사용자 역할

| Actor | 소속 | 역할 설명 | 시스템 내 주요 권한 |
|-------|------|----------|-------------------|
| **고객** | 외부 (시공사, 외주업체) | 주문 요청, 주문의뢰서 초안 확인 및 승인 | 조회, 승인 |
| **공사관리부** | 동일유리 현장 | 고객 주문정보 확인, 시스템에 주문정보 입력, 주문의뢰서 작성 | 입력, 조회, 모니터링 |
| **경영지원팀** | 동일유리 본사 | 주문 데이터 검토, ERP 입력 데이터 확인 | 검토, 수정, ERP 연동 |
| **관리자(경영진)** | 동일유리 본사 | 최종 승인, 전체 현황 모니터링 | 승인, 대시보드 조회 |
| **생산관리팀** | 동일유리 공장 | 생산실적 입력, 생산 현황 관리 | 생산실적 입력, 조회 |
| **시스템 관리자** | - | 마스터 데이터 관리, 사용자 관리 | 전체 관리 권한 |

### 4.2 사용자별 핵심 유스케이스

```
[공사관리부]
  UC-01: 주문정보 입력
  UC-02: 주문의뢰서 생성
  UC-03: 고객에게 초안 전송
  UC-04: 본인 주문 현황 모니터링
  UC-05: 본인 주문의 생산 현황 조회

[고객]
  UC-06: 주문의뢰서 초안 확인
  UC-07: 주문의뢰서 승인/반려

[경영지원팀]
  UC-08: 주문 데이터 검토
  UC-09: 주문 데이터 수정/보완
  UC-10: ERP 입력 데이터 생성 및 다운로드

[관리자(경영진)]
  UC-11: 주문 최종 승인/반려
  UC-12: 전체 주문 현황 대시보드 조회
  UC-16: 지역별/기간별 주문 통계 분석
  UC-17: 주문 처리 현황 실시간 모니터링

[생산관리팀]
  UC-13: 작업의뢰서 조회
  UC-14: 생산실적 입력 (복층/재단)
  UC-15: 생산 현황 모니터링
```

## 5. 기능 요구사항

### 5.1 영역 1: 주문의뢰서 → ERP 입력 프로세스

#### FR-01: 주문정보 입력

| 항목 | 내용 |
|------|------|
| **설명** | 공사관리부 담당자가 고객의 주문 정보를 웹 시스템에서 표준화된 양식으로 입력한다 |
| **Actor** | 공사관리부 |
| **선행조건** | 로그인 완료, 거래처/현장 마스터 등록 |
| **입력 데이터** | 거래처, 현장명, 주문일자, 납품일자, 품목 상세(품명, 규격, 수량, 위치정보, 비고) |
| **처리 로직** | 1. 거래처/현장 검색 및 선택 (마스터 기반)<br>2. 품목 행 추가/삭제<br>3. 품명 선택 (마스터 기반, 자동완성)<br>4. 규격(가로×세로) 입력 (mm 단위)<br>5. 수량 입력<br>6. 위치정보 구조화 입력: {동}동 {라인}라인({층}) {창위치} {타입} {내/외창}<br>7. 면적(m2) 자동 계산: 가로(mm) × 세로(mm) × 수량 / 1,000,000<br>8. 두께 자동 계산 (품명 기반) |
| **출력** | 주문정보 저장 (상태: 초안) |
| **우선순위** | 필수 |

#### FR-02: 주문의뢰서 자동 생성

| 항목 | 내용 |
|------|------|
| **설명** | 입력된 주문정보를 기반으로 표준화된 주문의뢰서를 자동 생성한다 |
| **Actor** | 공사관리부 |
| **선행조건** | FR-01 완료 (주문정보 입력) |
| **처리 로직** | 1. 입력된 품목 데이터를 주문의뢰서 양식에 매핑<br>2. 품명별 소계 자동 계산 (수량, 면적)<br>3. 전체 합계 자동 계산<br>4. 주문의뢰서 미리보기 제공<br>5. PDF/엑셀 출력 기능 |
| **출력** | 주문의뢰서 문서 (화면 미리보기 + PDF/엑셀 다운로드) |
| **우선순위** | 필수 |

#### FR-03: 고객 승인 프로세스

| 항목 | 내용 |
|------|------|
| **설명** | 주문의뢰서 초안을 고객에게 전송하고 승인을 받는다 |
| **Actor** | 공사관리부 (전송), 고객 (승인/반려) |
| **선행조건** | FR-02 완료 (주문의뢰서 생성) |
| **처리 로직** | 1. 공사관리부가 고객에게 초안 전송 (이메일 또는 링크 공유)<br>2. 고객이 주문의뢰서 내용 확인<br>3. 고객이 승인 또는 반려(사유 입력)<br>4. 반려 시 공사관리부에 알림, 수정 후 재전송<br>5. 승인 시 상태 변경 → 경영지원팀 검토 단계로 자동 전달 |
| **상태 변경** | 초안 → 고객승인대기 → 고객승인완료 (또는 → 반려 → 수정 → 재전송) |
| **우선순위** | 필수 |

#### FR-04: 경영지원팀 검토

| 항목 | 내용 |
|------|------|
| **설명** | 고객 승인이 완료된 주문 데이터를 경영지원팀이 검토한다 |
| **Actor** | 경영지원팀 |
| **선행조건** | FR-03 완료 (고객 승인) |
| **처리 로직** | 1. 고객 승인 완료된 주문 목록 조회<br>2. 주문 상세 데이터 검토 (품명, 규격, 수량, 위치 등)<br>3. 필요 시 데이터 보완/수정 (수정 이력 기록)<br>4. 품명 변환 확인: 발주서 표기 → ERP 표기 자동 매핑 검증<br>5. 규격 그룹핑 결과 검토 (동일 품명+규격 묶음)<br>6. 검토 완료 처리 → 관리자 승인 단계로 전달 |
| **상태 변경** | 고객승인완료 → 검토중 → 검토완료 |
| **우선순위** | 필수 |

#### FR-05: 관리자(경영진) 승인

| 항목 | 내용 |
|------|------|
| **설명** | 경영지원팀 검토가 완료된 주문을 관리자(상급자)가 최종 승인한다 |
| **Actor** | 관리자(경영진) |
| **선행조건** | FR-04 완료 (경영지원팀 검토) |

## 9. 규격 그룹핑 규칙

ERP 입력 시 동일 품명+동일 규격 항목을 묶는 규칙 (FR-06에서 적용):

| # | 규칙 | 예시 |
|---|------|------|
| 1 | 동일 품명 + 동일 규격(가로×세로)인 항목끼리 묶음 | - |
| 2 | 라인 번호 통합: 연속이면 `1~3`, 불연속이면 `1,2` | 1라인+2라인+3라인 → 1~3라인 |
| 3 | 타입 통합: 동일 규격의 다른 타입을 병합 | 59A+59B → 59A,B |
| 4 | 창 위치 통합: 동일 규격의 다른 위치를 병합 | 침실2+침실3 → 침실2,3 |
| 5 | 수량은 단순 합산 | 6+6+5 = 17 |

**그룹핑 결과 예시:**

| 원본 (개별 행) | 그룹핑 결과 |
|--------------|-----------|
| 302동1라인(1~6층)거실59A외창픽스 × 6<br>302동2라인(1~6층)거실59B외창픽스 × 6<br>302동3라인(2~6층)거실59A외창픽스 × 5 | 302동1~3라인(1~6층)거실59A,B외창픽스 × 17 |

| **승인 프로세스** | 비공식적 (유선/메신저 확인) | 체계적 4단계 워크플로우 | 추적 가능, 책임 명확 |
| **모니터링** | 불가능 (개별 문의 필요) | 실시간 웹 대시보드 | 의사결정 속도 향상 |
| **ERP 입력** | 수작업 엑셀 가공 후 import | 자동 생성 후 import | 입력 시간 단축, 오류 제거 |
| **생산실적** | 수기 작성 → 엑셀 입력 | 웹/모바일 입력 → 자동 집계 | 관리 비용 절감 |

## 15. 용어 사전

| 용어 | 의미 |
|------|------|
| **복층유리** | 2장 이상의 유리판 사이에 공기/가스층을 둔 단열유리 (Insulated Glass Unit) |
| **재단** | 대형 원판 유리에서 필요한 크기로 절단하는 공정 |
| **원판** | 재단 전의 대형 유리판 (표준 규격: 2438×3353mm 등) |
| **로이(Low-E)** | 저방사 코팅 유리 (EMT178, 로이, LE 등으로 표기) |
| **접합유리** | PVB 필름으로 2장의 유리를 접합한 안전유리 |
| **아르곤(Ar)** | 단열 성능 향상을 위해 복층유리 사이에 충전하는 불활성 가스 |
| **간봉** | 복층유리 사이 공간을 유지하는 스페이서 (알루미늄, 단열간봉 등) |
| **작업의뢰서** | ERP에서 출력되는 생산 지시 문서 (의뢰번호 기반) |
| **주문의뢰서** | 고객 주문을 내부 표준으로 정리한 문서 (본 시스템의 핵심 산출물) |
| **절단일보** | 재단 공정의 일간 생산실적 보고서 |
| **복층생산일지** | 복층유리 생산 공정의 일간 생산실적 보고서 |
| **오도시** | 소량 건으로 재단기에 올리지 않고 수작업 절단하는 방식 |
| **조(組)** | 복층유리 생산 단위 (외판+내판 1세트) |
| **수량외** | 팔레트(조) + 잔여 매수 표기 (예: "2조외24") |
| **바이투** | 동일유리가 사용하는 ERP 시스템 명칭 |
| **MES** | 생산실행시스템, 바코드 라벨 출력 및 생산 추적 |
| **카자리** | 건물 외장 장식용 유리 (커튼월과 유사) |
| **글레이징** | 유리 시공 방식 (실리콘 글레이징 등) |
| **강강과변** | 강화유리의 과변(과도한 휨) 현상 |
| **공사관리부** | 동일유리의 현장 영업/관리 조직. 고객과 직접 소통하여 주문을 수신 |
| **경영지원팀** | 동일유리 본사. 주문 데이터 표준화, ERP 입력, 관리 업무 담당 |
