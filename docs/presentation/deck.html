DG-Flow 소개 및 시연2
Why

지금, 같은 데이터를 세 번 옮겨 적고 있습니다

고객 → 공사관리부(담당자별 엑셀) → 경영지원팀(표준 양식으로 재작성) → ERP 입력

1양식이 제각각

담당자마다 다른 엑셀을 씁니다. 시트 수가 1개인 것부터 32개인 것까지 있습니다.

2이중 변환

공사관리부가 만든 것을 경영지원팀이 표준 양식으로 다시 만듭니다. 같은 숫자를 두 번 칩니다.

3표기 불일치

발주서의 5CL/0.76PVB/5CL+10ALC+6EMT178를 ERP 표기로 사람이 매번 바꿉니다.

4진행 상황 불투명

이 주문이 승인됐는지, 생산이 얼마나 됐는지 전화하거나 물어봐야 압니다.

5생산실적 수기

작업의뢰서에 손으로 적고, 그것을 다시 엑셀에 칩니다.

공통점

다섯 가지 모두 사람이 옮겨 적는 과정에서 생깁니다. 옮겨 적는 횟수를 줄이면 함께 사라집니다.

반려도 흐름의 일부

고객이 반려하면 ‘수정중’으로 돌아가고, 관리자가 반려하면 ‘재검토’로 갑니다. 되돌아가는 길까지 설계돼 있습니다.

모든 단계가 기록됩니다

누가 언제 어떤 상태로 바꿨는지 남습니다. 나중에 “그때 누가 승인했지?”를 찾을 수 있습니다.

단계마다 알림

상태가 바뀌면 관련된 역할에게 자동으로 알림이 갑니다. 기다리는 사람이 먼저 압니다.

동작 방식6
For you

역할별로, 무엇이 달라집니까

공사관리부 — 안광식 · 이충언 · 김길홍 · 오동석

  • 쓰시던 엑셀을 그대로 올리시면 됩니다. 양식을 바꾸실 필요 없습니다
  • 고객 승인은 링크를 보내고 결과를 기다리면 됩니다
  • 본인이 만든 주문만 수정·삭제할 수 있습니다

경영지원팀 — 이지원

  • 표준 양식으로 재작성하는 일이 없어집니다
  • 검토 화면에서 품명·규격만 확인하시면 됩니다
  • ERP 엑셀은 버튼 한 번으로 나옵니다

관리자·경영진 — 김경영

  • 대시보드에서 전체 현황을 한 화면에 봅니다
  • 최종 승인 시 작업의뢰서가 자동으로 만들어집니다
  • 납기 임박 주문과 거래처별 실적을 바로 확인합니다

생산관리팀 — 최생산

  • 작업의뢰서를 화면에서 보고 실적을 바로 입력합니다
  • 전량 완료는 버튼 하나로 처리됩니다
  • 복층·재단 이력이 한 화면에 모입니다

이제 실제 화면으로 보시겠습니다

주문 한 건을 접수부터 생산 지시까지 끝까지 따라가겠습니다. 역할이 바뀔 때마다 계정을 바꿔 로그인하므로, 본인 화면이 나올 때 유심히 봐 주십시오.
순서누구의 화면보실 것
1공사관리부실제 발주서 엑셀을 올려 품목이 자동으로 채워지는 장면
2공사관리부주문의뢰서 미리보기 — 인쇄하면 나오는 실제 양식
3고객 외부승인 링크를 열어 로그인 없이 승인하는 화면
4경영지원팀검토 처리와 ERP 엑셀 자동 생성
5관리자최종 승인 → 작업의뢰서가 저절로 만들어지는 순간
6생산관리팀생산실적 입력과 진행률 반영
7관리자대시보드에 방금 그 주문이 반영된 모습
중간에 멈추셔도 됩니다. “우리는 이렇게 안 하는데” 싶은 장면이 나오면 그때 바로 말씀해 주시는 편이 나중에 문서로 받는 것보다 훨씬 정확합니다.
